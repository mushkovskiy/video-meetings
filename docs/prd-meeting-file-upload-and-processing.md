# PRD: Загрузка записи встречи и её транскрипция

**Дата**: 2026-10-03
**Статус**: Draft

## Цель

Пользователь прикрепляет к встрече аудио- или видеозапись и получает её текстовую расшифровку внутри встречи. Так содержание встречи доступно для чтения без повторного прослушивания.

## Пользовательские сценарии

- Пользователь открывает встречу из списка на дашборде -> видит страницу встречи с названием, описанием, датой и блоком «Запись».
- Пользователь выбирает на странице встречи файл записи (mp3, wav, m4a, mp4, webm) до 100 МБ -> файл загружается, во время загрузки виден прогресс, после загрузки отображаются имя файла, размер и статус «В обработке».
- Пользователь ждёт окончания обработки -> статус меняется на «Готово», на странице встречи появляется текст транскрипции.
- Пользователь закрывает страницу во время обработки и возвращается позже -> видит актуальный статус и, если обработка завершена, транскрипцию.
- Пользователь выбирает файл неподдерживаемого формата или больше 100 МБ -> файл не загружается, пользователь видит сообщение с причиной (формат или размер).
- Обработка завершается ошибкой -> статус «Ошибка», пользователь видит сообщение и может загрузить файл заново.
- Пользователь загружает новый файл во встречу, где запись уже есть -> после подтверждения предыдущий файл и его транскрипция удаляются, новый файл проходит обработку с нуля.
- Пользователь пытается загрузить файл или получить транскрипцию чужой встречи -> получает отказ в доступе.

## В скоупе

- Страница отдельной встречи (переход из списка встреч на дашборде): название, описание, дата, блок «Запись».
- Загрузка одного файла записи на встречу; поддерживаемые форматы: mp3, wav, m4a, mp4, webm; максимальный размер 100 МБ.
- Проверка формата и размера: на клиенте до отправки и на сервере.
- Индикатор прогресса загрузки.
- Хранение загруженного файла, привязанного к встрече.
- Асинхронная транскрипция загруженного файла.
- Статусы записи: «Загружается», «В обработке», «Готово», «Ошибка».
- Отображение метаданных файла: имя, размер, дата загрузки, статус.
- Отображение текста транскрипции на странице встречи после завершения обработки.
- Актуализация статуса на странице без ручной перезагрузки.
- Замена файла с подтверждением: старый файл и его транскрипция удаляются.
- Повторная загрузка после ошибки обработки.
- Доступ к файлу и транскрипции есть только у владельца встречи.

## Не в скоупе

- Несколько файлов на одну встречу.
- Воспроизведение и скачивание записи из интерфейса.
- AI-саммари, извлечение задач и решений.
- Разделение транскрипции по спикерам (диаризация) и тайм-коды.
- Редактирование, поиск по тексту и экспорт транскрипции.
- Запись встречи прямо в браузере.
- Файлы больше 100 МБ, загрузка частями, возобновление прерванной загрузки.
- Удаление записи без замены.
- Доступ к записи для других участников встречи.
- Уведомления о завершении обработки (email, push).

## Технические ограничения

- В бэкенде сейчас нет хранилища файлов; файлы до 100 МБ нельзя хранить внутри документа MongoDB (лимит 16 МБ на документ).
- Во фронтенде нет страницы отдельной встречи: есть только список на дашборде и `GET /meetings/:meetingId` на бэкенде.
- Транскрипция длится дольше HTTP-запроса, поэтому результат нельзя возвращать в ответе на загрузку.
- Транскрипция выполняется локально на бэкенде моделью Whisper через библиотеку Transformers.js (`@huggingface/transformers`). Сторонние API транскрипции не используются: это pet-проект, и для тестового сценария локальной модели достаточно.
- Локальная модель работает на CPU медленно: расшифровка длинной записи может занять дольше её длительности и сильно нагружает сервер. Для этой итерации это допустимо.
- При первом запуске модель скачивается (сотни мегабайт) и должна храниться на сервере.
- Модель принимает только декодированное аудио (16 кГц, моно), поэтому mp3 / wav / m4a / mp4 / webm перед расшифровкой нужно декодировать, а из видео — извлечь звуковую дорожку.
- 100 МБ хватает примерно на 1–1,5 часа аудио, но лишь на несколько минут видео в высоком качестве. Длинные видеозаписи в лимит не поместятся.
- Существующее правило доступа (только владелец, `403` для чужой встречи) должно действовать и для файла, и для транскрипции.
- Бэкенд-код должен соответствовать `docs/ARCHITECTURE_PRINCIPLES.md`.

## Критерии готовности

- [ ] Клик по встрече в списке на дашборде открывает страницу этой встречи с названием, описанием, датой и блоком «Запись».
- [ ] Файлы mp3, wav, m4a, mp4 и webm размером до 100 МБ успешно загружаются.
- [ ] Файл больше 100 МБ отклоняется на клиенте без отправки запроса; при прямом запросе к API сервер возвращает `413`.
- [ ] Файл неподдерживаемого формата (например, `.pdf`) отклоняется на клиенте; при прямом запросе к API сервер возвращает `4xx` с понятным сообщением.
- [ ] Во время загрузки виден прогресс в процентах.
- [ ] После загрузки отображаются имя файла, размер, дата загрузки и статус «В обработке».
- [ ] После завершения транскрипции статус меняется на «Готово», и на странице появляется текст без перезагрузки страницы.
- [ ] После перезагрузки страницы статус и транскрипция отображаются корректно.
- [ ] Если обработка упала, отображается статус «Ошибка», и можно загрузить файл заново.
- [ ] Загрузка нового файла во встречу с существующей записью требует подтверждения; после замены старые файл и транскрипция недоступны.
- [ ] Загрузка файла и чтение транскрипции чужой встречи возвращают `403`, несуществующей встречи — `404`, без авторизации — `401`.
- [ ] Бэкенд e2e-тесты покрывают загрузку, валидацию размера и формата, замену файла и проверки доступа.
- [ ] Фронтенд e2e-тест (Playwright) покрывает открытие встречи, загрузку файла и отображение статуса.
- [ ] UI проверен через Playwright MCP и skill `ui-ux-pro-max`, все замечания исправлены.
